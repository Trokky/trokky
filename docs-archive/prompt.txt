I'm working on Trokky v2, a modern composable CMS designed as a true alternative to Sanity. This is a complete rewrite focused on simplicity, developer experience, and framework freedom.

REFERENCE PROJECT:
The original Trokky project is located at ../trokky/ (one level up) and serves as reference for:
- Understanding CMS domain concepts and requirements
- Field types and validation patterns
- Storage adapter interfaces
- Studio UI patterns and components
- API design patterns
However, DO NOT copy code from the original - we're building from scratch with a simplified architecture.

KEY PROJECT CONTEXT:
- Local-first development with Git-friendly workflows
- Framework-agnostic architecture (works with Express, Next.js, Cloudflare Workers, etc.)
- TypeScript native with full type safety
- Modular package system for composability
- Built-in Sanity migration tools

CURRENT STATUS:
- Project structure and specifications are complete
- Ready to begin implementation starting with @trokky/core package
- All architectural decisions documented in /docs/specs/

ARCHITECTURE OVERVIEW:
- @trokky/core: CMS engine and business logic
- @trokky/routes: Framework-agnostic HTTP handlers
- @trokky/studio: React admin interface
- @trokky/client: Frontend SDK
- @trokky/integrations/*: Framework-specific adapters
- @trokky/adapters/*: Storage backends

NEXT STEPS:
1. Implement @trokky/core package (schemas, validation, storage interface)
2. Create @trokky/routes with framework-agnostic handlers
3. Build @trokky/express integration for validation
4. Create working blog example to prove concept

Please read the project specifications in /docs/specs/ to understand the full scope and begin implementation of the core package.
